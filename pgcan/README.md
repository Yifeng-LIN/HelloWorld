# 巴黎(CDG) ↔ 广州(CAN) 航线历史客座率工具

目标：搞清楚这条航线**每月/每周的历史满座程度**，用来决定什么时候买票、
避开一票难求的时段。

---

## 一、先说航线本身（2026-08 核实）

| 项目 | 事实 |
|---|---|
| 直飞承运人 | **只有中国南方航空一家**（CZ348 CDG→CAN，CZ347 CAN→CDG） |
| 班次 | 每周 7 班，每天一班往返 |
| 机型 | A350-900，**314 座**（28 商务 + 24 超经 + 262 经济） |
| 旺季机型 | 2026 年 7/1–8/31 换 **777-300ER，309 座**（4 头等 + 34 商务 + 44 超经 + 227 经济） |
| 法航 | **2019 年 3 月底已停飞**该航线，之后只做代码共享，不投运力 |

这两点对分析非常关键：

1. **运力分母极其干净。** 只有一家承运人、每天一班、机型固定，
   所以「月度座位数 ≈ 当月天数 × 314」。不用去拼多家航司的复杂班表。
2. **南航专门在 7–8 月换成 777-300ER**，本身就是最硬的需求信号 ——
   航司不会为了好玩去换宽体机型。暑运是全年最紧张的时段，这一点不需要
   等数据来证明。

## 二、数据源分级：哪些拿得到，哪些拿不到

我把所有能想到的路子都过了一遍，结论如下。

### ✅ 第一梯队：免费、官方、能直接算出真实客座率

**Eurostat `avia_par_fr`** —— 唯一一个同时给出分子和分母的免费官方源。

- 数据集：*Air passenger transport routes between partner airports and main airports in France*
- 粒度：**月度 × 航线级**（CDG ↔ 广州白云单独成行）
- 关键字段：
  - `ST_PAS` = 可提供座位数（分母）
  - `PAS_CRD` = 实际承运旅客数（分子）
  - `CAF_PAS` = 商业客运航班班次
- **客座率 = `PAS_CRD` / `ST_PAS`**
- 航线代码：`FR_LFPG_CN_ZGGG`
- 接口：`https://ec.europa.eu/eurostat/api/dissemination/statistics/1.0/data/avia_par_fr?format=JSON&freq=M&airp_pr=FR_LFPG_CN_ZGGG`

对应命令：`python -m pgcan monthly`

### ✅ 第二梯队：免费、官方、只有分子（旅客数）

**法国民航局 DGAC，data.gouv.fr 上的开放数据**

- 数据集：《法国商业航空月度运量，按机场对、按方向，1990 年起》
- 序列名 `ASP_LSN_AAAA`，CSV
- 优势：**历史最长（1990 年起）**，而且**分方向**（去程/回程分开），
  能看到法航时代到南航独家时代的完整需求曲线
- 局限：主要是旅客数，座位数字段不稳定；且**年度更新、滞后约 3 个月**
- 坑：列名多年间改过好几轮 → 工具里用模糊匹配，并提供 `dgac-inspect` 先看表头

对应命令：`python -m pgcan dgac-inspect` → `python -m pgcan dgac`

### ✅ 第三梯队：能做到「逐周/逐日」的唯一免费路子

官方统计最细只到「月」，而且滞后好几个月。想知道**具体哪一周满**，
只能从订座系统侧取实时信号。**Amadeus Self-Service API**（注册免费）：

- **Flight Availabilities Search** → 每个舱位等级的可订座位数（计数器上限 9）。
  低舱（L/V/X/N/Q…）全关、只剩高舱开着 = 航班快售罄。**这是对「快满了」最敏感的指标。**
- **SeatMap Display** → 每个座位的 `AVAILABLE` / `BLOCKED` / `OCCUPIED`，
  已占座位占比 = 已选座满座率。

对应命令：`python -m pgcan weekly --start 2026-09-01 --days 180`

### ❌ 拿不到 / 要花钱的

| 来源 | 情况 |
|---|---|
| **OAG Traffic Analyser** | 航线级客座率，2019 年起，基于 MIDT。**商业订阅**，最贵但最权威 |
| **Cirium Diio Mi / FM Traffic** | 航线级运量+票价+客座率，20 年历史。**商业订阅** |
| **IATA DDS** | 商业订阅 |
| **飞常准 VariFlight 大数据平台** | 中国侧航线数据，有航线客座率产品，**商业授权** |
| **南航月度运营数据公告** | 免费，但**只到「国际航线」整体客座率**，不拆到具体航线 |
| **法荷航月度流量报告** | 免费，但只到「亚洲区域」，且法航已不飞这条线，参考价值有限 |
| **CAAC / 白云机场公告** | 只有机场总吞吐量，不拆航线 |

> 一句话：**航线级 + 逐月客座率，免费的只有 Eurostat 这一条路。**
> 想要逐周，只能自己扫订座库存。

## 三、怎么用

```bash
pip install -r requirements.txt

# 1) 月度真实客座率 + 季节指数（核心，先跑这个）
python -m pgcan monthly -v

# 若航线代码变了，先探测：
python -m pgcan probe-codes

# 2) DGAC 长历史（1990 起，分方向）
python -m pgcan dgac-inspect      # 先看表头长什么样
python -m pgcan dgac

# 3) 逐周满座探测（需要 Amadeus 免费 key）
export AMADEUS_CLIENT_ID=xxx
export AMADEUS_CLIENT_SECRET=xxx
python -m pgcan weekly --start 2026-09-01 --days 180 -v
```

产出全部写到 `out/`：

- `monthly.csv` —— 逐月客座率原始序列
- `seasonal.csv` —— 12 个月季节指数（**>1 = 比全年平均更满**）
- `monthly.png` —— 时间序列图 + 季节指数柱状图
- `daily_CDG_CAN.csv` / `weekly_CDG_CAN.csv` —— 逐日/逐周紧张度
- `dgac_route.csv` —— DGAC 分方向旅客数

离线自检（不联网，验证分析链路）：

```bash
python tests/test_offline.py
```

## 四、方法论与几个必须知道的坑

**1. 季节指数怎么算的**
直接按月求平均会被长期趋势和疫情断档污染（2020–2022 这条航线基本停摆）。
所以先用 12 个月居中滚动均值抹平趋势，再取每月相对趋势的比值，
最后归一化到均值 1。这样得到的是**纯季节性**，不含增长趋势。

**2. 座位图占用率会系统性偏低**
很多人值机前不选座，后排常被航司锁座。所以 `seatmap_occupancy`
**只能横向比较**（这周 vs 那周），不能当绝对客座率读。
判断「是不是快满了」，看 `scarcity` 和 `low_classes_open` 更准。

**3. 方向必须分开看**
这条航线两个方向的季节性是**错位**的。春节前 CDG→CAN 满、节后 CAN→CDG 满；
9 月开学季 CAN→CDG 满。用双向合计的数会把两个峰抹平。
DGAC 数据分方向，务必分开跑。

**4. 2020–2022 的数据要剔掉**
疫情期间这条航线运力被砍到极低，客座率受五个一政策、熔断机制扭曲，
不能用来推断正常年份的季节性。建议只用 **2015–2019 + 2024 至今**。

**5. 不要拿「客座率高」直接等于「买不到票」**
客座率是全舱平均。经济舱低价舱位往往在客座率到 80% 之前就已经卖光了。
真正决定「便宜票还有没有」的是**低舱库存**，不是客座率。
所以 `weekly` 命令给的 `low_classes_open` 其实比月度客座率更贴近你的实际问题。

## 五、关于本仓库里没有的东西

这套代码是在一个**只放行 GitHub 出网**的沙箱里写的，
`ec.europa.eu`、`data.gouv.fr`、`huggingface.co` 全部被 403 拦截，
所以**我没能在这里跑出真实数字**。

代码的解析、透视、季节指数、运力推算等全部逻辑已用构造数据端到端验证
（见 `tests/test_offline.py`，季节形态能被正确还原）。
网络部分请在你自己的机器上跑 —— 那边没有这个限制。

仓库里**没有任何编造的客座率数字**。`data/schedule_cz_cdg_can.json`
里只写了经过核实的班期时段，未核实的月份运力函数返回 `None` 而不是猜一个值。
